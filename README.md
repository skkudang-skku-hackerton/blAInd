# blAInd

AI 웹사이트에 질문을 보내기 전에 개인정보를 감지하고, 사용자 선택에 따라 마스킹하는 크롬 확장 프로그램입니다. 텍스트 검사와 모델 추론은 사용자 기기에서 처리하도록 개발합니다.

## 예정 기술 스택

- 확장 프로그램: WXT, Manifest V3
- 화면: React, TypeScript
- 로컬 추론: ONNX Runtime Web, Web Worker
- 추론 환경: Offscreen Document, WebGPU 또는 WASM
- 설정 저장: `chrome.storage.local`

모델 개발은 별도 레포에서 진행합니다. 이 레포는 전달받은 모델과 토크나이저를 브라우저에서 실행하고, 탐지 결과를 마스킹 및 전송 흐름에 연결합니다. 브라우저 실행 호환성은 실제 모델 연결 단계에서 확인합니다.

모델 라이브러리 API는 `docs/pii-detection-model-api.md`를 참고해주세요.

`public/models/`의 모델 파일은 `.gitignore`로 제외합니다. 모델 연결 단계에서 사용할 버전과 파일을 가져오는 방법을 정합니다.

## 사용자 흐름

```text
AI 웹페이지에서 텍스트 입력 → Enter 또는 전송 버튼
  → 원래 전송 보류 → 로컬 개인정보 검사
      ├─ 민감정보 없음 → 원문 전송
      └─ 민감정보 있음 → 사용자 확인
                            ├─ 마스킹 동의 → 내용 교체 후 전송
                            ├─ 원문 전송 선택 → 원문 전송
                            └─ 취소 → 입력 상태로 복귀
```

검사 중 중복 전송, 한글 조합 중 Enter, 줄바꿈, 검사 후 입력 변경을 구분합니다. 검사 오류가 발생하면 전송을 보류하도록 구현합니다.

## 디렉토리

```text
blAInd/
├── src/
│   ├── entrypoints/          # 확장 프로그램 진입점
│   │   ├── app.content/      # 웹페이지 감지 및 사이트 연동 시작
│   │   ├── offscreen/        # 로컬 추론 Worker 실행 환경
│   │   └── popup/            # 확장 활성화 및 설정 화면
│   ├── sites/                # 사이트 연동 규약과 URL 등록 정보
│   │   └── adapters/         # 사이트별 입력창 읽기·교체·전송
│   ├── features/
│   │   └── submission/       # 검사·동의·전송 상태와 확인창
│   ├── pii/                  # 탐지 결과 타입과 마스킹 처리
│   ├── inference/            # 모델 로딩, 토큰화, 추론 및 개발용 탐지기
│   ├── documents/            # 추후 파일 추출·탐지·재생성 흐름
│   │   ├── docx/             # Word 문서 처리
│   │   └── pdf/              # PDF 문서 처리
│   └── shared/               # 확장 내부 메시지 타입과 설정
├── public/
│   └── models/               # 로컬 모델·토크나이저 등 배포 자산 위치
├── tests/
│   ├── unit/                 # 추후 마스킹·상태 전이 단위 테스트
│   └── e2e/                  # 추후 사이트별 전체 전송 흐름 테스트
├── .gitignore
└── README.md
```

`background.ts` 등 진입점 파일과 WXT 설정은 프로젝트 실행 환경을 구성할 때 추가합니다. 위 폴더 이름은 역할 분담을 위한 기준이며, 실제 구현에 필요한 파일만 추가합니다.

## 팀 작업 경계

| 작업 | 주로 수정할 경로 | 연결할 부분 |
| --- | --- | --- |
| 확장 기반·설정 | `src/entrypoints/`, `src/shared/` | 메시지 규약, 추론 환경 수명 관리 |
| 사이트 연동 | `src/sites/` | 입력 읽기·교체·전송 인터페이스 |
| 전송 흐름·확인창 | `src/features/submission/` | 사이트 연동과 개인정보 검사 |
| 모델 연결·마스킹 | `src/inference/`, `src/pii/` | 별도 모델 레포의 산출물 |
| 문서 지원 | `src/documents/` | 기존 탐지기와 파일 재생성 |

URL 등록은 확장이 실행될 페이지를 정합니다. 각 사이트의 입력창과 전송 방식 차이는 `sites/adapters/`에서 처리하고, 검사·확인창·마스킹 로직은 공통 모듈에서 재사용합니다.

병렬 개발 전에 사이트 연동 인터페이스, 확장 내부 메시지, 탐지 결과 타입을 함께 정합니다. 탐지 구간은 JavaScript의 `text.slice(start, end)`와 일치하도록 인덱스 기준을 맞춥니다. 모델이 준비되기 전에는 개발용 가짜 탐지기를 연결해 화면과 전송 흐름을 개발할 수 있습니다.

## 추후 Word/PDF 지원

파일은 확장에서 먼저 선택해 검사하고, 사용자 동의 후 **마스킹된 새 Word/PDF 파일을 생성하여 사이트에 첨부**하는 흐름으로 확장합니다. 원본 파일이 먼저 업로드되지 않도록 파일 처리 경로를 별도로 구성합니다.

`documents/`는 추출한 텍스트와 원본 문서 위치의 연결, 내용 제거·치환, 파일 재생성을 담당합니다. 개인정보 탐지는 `pii/`와 `inference/`를 재사용합니다. PDF는 화면에 덮어 그리는 처리만으로 끝내지 않고 원본의 민감한 내용도 제거해야 합니다.

## 개발 시작 순서

1. WXT·React·TypeScript 실행 환경과 공통 인터페이스를 구성합니다.
2. 개발용 탐지기로 사이트 하나의 전송 보류·확인창·전송 흐름을 완성합니다.
3. 별도 레포의 모델을 연결하고 로컬 추론을 확인합니다.
4. 사이트 어댑터와 Word/PDF 지원을 추가합니다.

`tests/`에는 현재 `.gitkeep`만 있습니다. 테스트 환경을 정한 뒤 동의 전 전송 방지, 승인된 내용의 한 번만 전송, 입력 변경 시 재검사 등의 동작을 검증합니다.
